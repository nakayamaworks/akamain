# あかマイン AI採点安定性評価（2026-09-05）

## 結論

既知の代表60回答では、同一回答を3回採点した際の点数と判定が完全一致した。

旧版 `practice-review.v37` で33.3%だった悪回答の点数安定率は、`practice-review.v39` で100%になった。原因だったGeminiの観点別点数を総合点計算から外し、構造化された事実判定による品質ゲート、チケット設定、証跡選択から総合点を決める方式へ変更した。

ただし、これは既知の15シナリオ・60回答に対する結果である。未知の自由回答や未調整ホールドアウトでも100%安定すると証明した結果ではない。

良回答と悪回答の一部が100点・40点から2点低いのは、上級シナリオの固定チケット設定差分による。Geminiの出力揺れではない。

## 実装した採点方針

1. Geminiの観点別点数は、説明用フィードバックとして保持するが総合点には使わない。
2. 重要事実の欠落、矛盾、回答不能なQA質問、重大な根拠なし断定から、決定論的な品質ゲートと点数上限を決める。
3. 品質ゲートが同じなら、その上限点をコンテンツ基準点として固定する。
4. チケット設定と証跡選択の客観的な誤りだけを固定点で減点する。
5. 全重要事項が欠落した悪回答は40点を基準にする。
6. 攻撃的・威圧的・採点操作目的の回答はGemini実行前に拒否し、技術内容にかかわらず40点・不合格とする。
7. 初級では出題範囲外を減点せず、改善指摘を重要な1〜2件へ限定する。

## テスト中に見つけて修正した問題

最初のv39全180回では、許容差10点以内の安定率は100%だったが、完全一致は58/60ケース（96.7%）だった。

- 車載バグ・中回答: `47 / 57 / 47`
- 決済QA・中回答: `40 / 49 / 49`

どちらも品質ゲートと最終判定は同じだったが、Geminiが非本質的な事実1件を「あり／なし」で揺らし、不足件数ベースの減点へ10点前後漏れていた。そこで、同じ品質ゲートなら基準点を同じ上限へ固定した。該当2ケースの再試験は `58 / 58 / 58` と `50 / 50 / 50`、最終180回も全件完全一致となった。

## 商品上の判断

今回の変更により、既知ケースにおける「同じ回答なのに点数が変わる」という商品上致命的な問題は解消した。少なくとも練習サービスのフィードバック点としては利用可能な状態である。

一方、点数は1点刻みの精密測定ではない。実態は、品質ゲートで決めた段階点に客観項目の差分を反映したものだ。ランキングや成長表示へ利用する場合も、この性質をUIと利用規約で隠してはいけない。

また、企業研修の合否、人事評価、採用、資格認定へ単独で使う段階ではない。次の必須工程は、今回の調整に使っていないホールドアウト回答をQA担当者が先に評価し、その後に同じ基準で反復テストすることである。

## 次の検証

1. 未調整ホールドアウト20回答をQA担当者が採点する。
2. コードを変更せず、各回答を3回実行する。
3. 点数完全一致率、判定一致率、必須指摘検出率を測る。
4. 自由記述の言い換え、部分的に正しい回答、矛盾を含む回答を追加する。
5. 攻撃ケースを難読化、多言語、分割入力、業務文への偽装まで拡張する。
